## 1. 目标与非目标

### 1.1 目标

从 NAND 门出发，自底向上复刻《图灵完备》的完整学习路径：玩家用 NAND 搭出所有基本逻辑门，进而搭出算术单元、存储器、8 位 CPU（OVERTURE → LEG），最后用汇编语言解决编程关卡。共 82 关、7 个章节。

### 1.2 非目标（本期不做）

- 在线排行榜后端、云存档、多人、成就同步
- 飞船 NPC 美术、角色立绘、对话演出
- 移动端触屏适配（桌面浏览器优先）

### 1.3 已确认的决策（来自头脑风暴）

| 决策点 | 结论 |
|---|---|
| 技术栈 | Web 网页版：TypeScript + Vite + Canvas 2D |
| 交付节奏 | 先可玩纵切片（第 1 章 12 关），再逐章扩展到 82 关 |
| 系统范围 | 玩法内核优先（引擎/关卡/评分/沙盒/存档）；外围用原创精简叙事外壳 |

### 1.4 版权边界（硬约束）

复刻**机制、关卡设计、教学曲线、界面布局**；**不复制**原作的任何美术资源、音频、文本原文、字体。所有视觉元素用程序化绘制或原创内容实现。叙事角色使用原创命名与原创台词。

本复刻是**学习与个人使用**用途的独立实现，与 LevelHead 无任何关联，不得用于商业分发或声称官方出品。仓库内 `LICENSE` 与 `README` 首段必须写明这一点。

## 3. 组件模型

### 3.1 端口与符号系统

所有信号只有两种取值：`0` / `1`。聚合信号用「宽位端口」表示，宽度在组件定义里声明（`width: 1 | 8 | 16 | 32 | 64`）。字节（8 位）端口在内部就是一个 `Uint8Array` 的 8 条子信号，绘制成一条粗线，拆合由 `Splitter` / `Maker` 组件负责。

不做「总线协议」（多驱动仲裁）。一个输入引脚只能有一根线驱动；违反即编辑期报错。

### 3.2 组件定义（ComponentDef）

```ts
interface ComponentDef {
  id: string;                       // 'nand' | 'add8' | 'ram' | ...
  name: { zh: string; en: string };
  category: 'logic1' | 'memory1' | 'wide' | 'io' | 'ram' | 'display' | 'probe' | 'level';
  pins: {
    inputs: PinDef[];               // { id, width, side }
    outputs: PinDef[];
  };
  delay: number;                    // 传播延迟，单位为「门延迟」，NAND = 1
  kind: 'combinational' | 'edge-triggered' | 'source';
  eval?: (inputs, outputs, ctx) => void;   // combinational / source
  onTick?: (inputs, outputs, ctx) => void; // edge-triggered
  cost?: number;                    // 基础门成本；未提供则运行时展开计算
  blueprint?: ComponentGraph;       // 由「蓝图」实现的组件（内部元件图）
  turingComplete?: boolean;         // 用于成就判定
}
```

**延迟约定**：每个组件恰好贡献 1 单位延迟（含 NOT、Buffer）。宽位组件（如 8 位加法器）同样记为 1 —— 但它的**内部蓝图**展开后路径延迟会累加，这是评分「延迟」的正式口径：**把电路连同自定义组件一起展开成基础门网络，取任一输入引脚到任一输出引脚的最长路径**。这样玩家封装组件不会「作弊」降低延迟。

### 3.3 组件清单（按解锁章节）

| 章节 | 解锁组件 |
|---|---|
| Ch1 基础逻辑 | `const_on` `const_off` `nand` `not` `and` `or` `nor` `xor` `xnor` `and3` `or3` `delay_line` |
| Ch2 算术与存储 | `switch` `full_adder` `decoder1` `decoder2` `decoder3` `mem1` `reg8` `counter8` `mux8` `switch8` `splitter` `maker` `const8` `add8` `neg8` `and8` `or8` `not8` `nand8` `nor8` `xor8` `xnor8` `less_s` `less_u` `equal8` `shift_l8` `shift_r8` `ashr8` `rot_l8` `rot_r8` `mul8` `div8` `delay8` |
| Ch3 CPU（OVERTURE） | `alu8` `regfile6` `instr_decoder` `pc8` `ram_prog` `halt` |
| Ch4 编程 | 无新元件；解锁汇编 IDE 与调试器 |
| Ch5 CPU2（LEG） | `ram256` `addr_reg` `ram_dual` `ram_fast` `ram_latency` |
| Ch6 函数 | `hd`（大容量存储）`byte_indexer` `bit_indexer` `configurable_delay` |
| Ch7 汇编挑战 + 外设 | `console` `dot_matrix` `seven_seg` `sprite` `sound` |
| 沙盒专用 | `program` `rom` `network` `keyboard` `file_loader` `time` `wire_probe` `wire_probe_bit` `mem_probe` `mem_probe_bit` |

**关于栈**：`stack` **不是内核元件**。栈在源资料里由 LEG 的 RAM + ADDR 寄存器实现（从 RAM 末字节向下生长）。玩家在第 6 章亲手用 `ram256` + `addr_reg` 搭出来——这正是《栈》关卡要教的东西。把它做成内置元件会直接抹掉这一关的意义。

**关于宽位组件**：16/32/64 位组件不是 60 多个独立内核实现，而是**同一套算子的宽度参数化**（`add8` / `add16` / `add32` / `add64` 共享一份定义生成器）。Ch6 完成后解锁宽位版本。

**关于 `switch`**：源资料把它列在第 1 章，但第 1 章 12 关没有任何一关需要条件通断。为了让「元件只在真正用到时才出现」这条教学原则成立，`switch` 顺延到第 2 章，与 `switch8` 一起在第 32 关《1 位开关》解锁。

**关卡 I/O 绑定约定**（实施计划中确定）：关卡不靠引脚同名绑定——引脚名由组件定义固定，改不了。`level_input` / `level_output` 是两个专用的 plumbing 元件（`hidden`，不进解锁体系、永远可用），实例 id 为 `IN_<引脚名>` 与 `OUT`（单输出）或 `OUT_<引脚名>`（多输出）。多比特引脚由实例 `params.width` 覆盖。

### 3.4 自定义组件（蓝图）

- 玩家可框选若干元件 → 「封装为组件」，进入蓝图编辑器定义暴露的引脚。
- 蓝图实例在仿真时**内联展开**（不复制状态，每个实例有独立状态槽）。
- 蓝图在评分时**递归展开**为 NAND 数量，因此「门数量」指标对封装完全透明。
- 蓝图保存进进度存档，可在后续关卡与沙盒中复用。
- 蓝图嵌套深度上限 8 层，防止递归蓝图导致无限展开；超限在编辑期报错。

## 4. 仿真内核

### 4.1 求值语义（关键设计）

采用**混合语义**：组合逻辑在「稳定化」阶段传播到不动点，存储元件只在时钟沿采样。

- `settle()`：反复遍历所有元件（依赖顺序），读取输入、调用 `eval()`、写输出；直到一轮内无任何值变化，或达到迭代上限（512 轮）。
- `tick()`：**先**快照所有 `edge-triggered` 元件的输入，**再**写回它们的新状态；随后 `settle()`。这样状态更新对同一拍内的其他元件不可见，避免竞争。
- 迭代超限（组合环无延迟元件）→ 抛 `UnstableCircuitError`，UI 显示「检测到不稳定回路」并高亮可疑元件。这是《循环依赖》关卡要教会玩家的东西，因此必须是**明确可读的错误**，而不是静默死循环。

### 4.2 时钟与 I/O

- 关卡在每个测试用例开始时调用 `reset()`：清空所有 `Uint8Array` 信号表、重置所有状态槽、重置时钟相位。
- 编辑器里的时钟按钮：`Tick`（单拍）、`Run`（连续跑，可调速度）、`Stop`。
- 关卡输入/输出使用 `level_input` / `level_output` 元件承载，引脚名来自关卡定义。

### 4.3 稳定性与性能预算

- 目标规模：≤ 20,000 个已展开元件实例。
- 单拍 `settle` 目标：≤ 5 ms（步进式评估，不递归，避免栈溢出）。
- 超预算时的行为：仍正确但更慢（先保证正确性）；性能优化列入后续阶段，不改语义。

### 4.4 模块边界

```ts
interface Simulation {
  load(graph: ComponentGraph): void;
  settle(): SettleReport;          // { iterations, stable, error? }
  tick(): void;                    // 时钟沿 + 稳定化
  read(slotBase: number, width: number): PortValue;
  write(slotBase: number, width: number, v: PortValue): void;
  reset(): void;
  snapshot(): SimSnapshot;         // 用于渲染与调试
}
```

> **按槽位而非按名字读写**（实施计划中修正）：内核暴露的是槽位编号，引脚名到槽位的解析由 `Netlist` 承担——`net.inputBase('i3.a')` / `net.outputBase('i3.out')`。这样关卡绑定与评分器各自只解析一次名字，热路径上不再有字符串查找。

`load` 接受已展开的图。展开器 `expand(graph, registry)` 负责把自定义组件与宽位组件内联，并产出 `Map<baseInstanceId, InstanceRef>` 供评分器统计代价。

## 5. 关卡系统

### 5.1 关卡数据格式（LevelSpec）

关卡是**纯数据**。新增关卡不需要改引擎代码。

```jsonc
{
  "id": "ch1-04-and-gate",
  "chapter": 1,
  "index": 4,
  "name": { "zh": "与门", "en": "AND Gate" },
  "brief": "……（原创文案）",
  "hint": "……（原创提示，默认折叠）",
  "allowedComponents": ["nand", "not"],
  "io": {
    "inputs":  [{ "id": "a", "width": 1 }, { "id": "b", "width": 1 }],
    "outputs": [{ "id": "out", "width": 1 }]
  },
  "checks": [
    { "kind": "truth-table", "rows": [
      { "inputs": { "a": 0, "b": 0 }, "outputs": { "out": 0 } },
      { "inputs": { "a": 0, "b": 1 }, "outputs": { "out": 0 } },
      { "inputs": { "a": 1, "b": 0 }, "outputs": { "out": 0 } },
      { "inputs": { "a": 1, "b": 1 }, "outputs": { "out": 1 } }
    ]}
  ],
  "targets": {
    "pass": {},
    "threeStar": { "gate": 20, "delay": 12, "tick": 4 }
  },
  "rewards": { "components": ["and"] }
}
```

### 5.2 验证器类型（Check 联合类型）

| kind | 用途 | 覆盖关卡举例 |
|---|---|---|
| `truth-table` | 显式给出全部输入组合与期望输出（**不允许省略 rows**，否则任何电路都会"通过"） | 所有逻辑门、加器、解码器 |
| `script` | 逐拍驱动输入、在指定拍断言输出与内部状态 | 延迟线、锁存器、计数器、CPU、总线 |
| `constraint` | 断言全局性质（如「4 个输入中至少 2 个为高」），由内核构造穷举向量 | 奇数个信号、成对的麻烦、信号计数 |
| `fuzz` | 随机向量 + 固定种子，重复 N 轮 | 8 位运算、ALU |
| `custom` | 关卡专属脚本钩子 | 迷宫、跳舞机、AI 对决、太空入侵 |

> **实施分期**：阶段 0（第 1 章 12 关）只落地 `truth-table` / `script` / `constraint` 三种。`fuzz` 与 `custom` 必须分别在开始第 2 章（8 位运算）与第 3 章（CPU）之前实现。

`custom` 是逃生舱，但必须只依赖内核公开接口，且必须能离线跑通（不抓网络、不读真实时间）。

### 5.3 章节与关卡清单

按源资料的 7 章 82 关结构实现，章节依次解锁：

| 章节 | 关卡数 | 主题 | 交付阶段 |
|---|---|---|---|
| Ch1 基础逻辑 | 12 | 逻辑门推导 | **阶段 0（纵切片）** |
| Ch2 算术与存储 | 26 | 运算电路 + 存储 | 阶段 1 |
| Ch3 CPU 架构 OVERTURE | 9 | 第一台 CPU | 阶段 2 |
| Ch4 编程 | 6 | 汇编入门 | 阶段 3 |
| Ch5 CPU 架构 LEG | 11 | 第二台 CPU | 阶段 4 |
| Ch6 函数 | 10 | RAM/栈/调用 | 阶段 5 |
| Ch7 汇编挑战 | 8 | 综合挑战 + 沙盒 | 阶段 6 |

关卡名沿用源资料的中英文对照表（关卡名是识别性标题，非艺术资产）。

### 5.4 评分系统

| 指标 | 精确定义 |
|---|---|
| **Gate（门数量）** | 电路 + 自定义组件 + 宽位组件全部展开后，**NAND 等价门**的总数。展开时每个基础门的贡献 = 1，`const`/`probe`/`level_*` 元件贡献 0 |
| **Delay（延迟）** | 展开后的基础门网络中，**任一关卡输入 → 任一关卡输出**的最长路径延迟。计数单位与 NAND 一致 |
| **Tick（时钟周期）** | 通过该关卡全部测试用例所消耗的最大时钟拍数，含 `reset` 后到首个断言之间 |

综合分 `score = gate + delay * 4 + tick * 8`（权值可调，写在配置里而非硬编码）。分数越低越好，与源资料的「高尔夫计分」一致。UI 分别显示三项指标与综合分，并显示个人最佳。

**星级**：通过测试 = 1 星；再满足 `targets.threeStar` 中的**全部**三项 = 3 星（不给 2 星，避免「接近最优」的模糊判定）。源资料里的 15 项成就**不在本期范围**，其引导玩家优化解法的作用由星级承担。

> 说明：源资料中若干关卡标注了成就式的硬指标（如「异或仅用 4 个 NAND」「全加器仅用 5 个元件」「8 位加法器延迟 ≤ 35」「计数器 ≤ 65 个门」「机器赛跑代码 < 64 字节」）。这些数值直接成为对应关卡的 `targets.threeStar` 门槛，是关卡数据的一部分，不需要单独的成就系统。

## 6. 汇编与 CPU 系统

### 6.1 CPU 是玩家搭出来的

OVERTURE 与 LEG 两套架构**不是内置模拟器**，而是玩家在第 3/5 章用元件搭出来的电路。引擎只提供元件与验证。这是复刻的核心难点，也是游戏的精髓。

### 6.2 汇编器（IDE）

IDE 是**面向玩家自建 CPU 的可配置汇编器**，而非写死某一套指令集：

- 玩家声明：指令宽度、字段布局（bit 范围）、助记符 → 字段值映射。
- 支持 `label` 定义（求值为其后第一条指令的索引）、`#` 注释、`|` 字段分隔。
- 产出二进制 → 注入 `program` / `rom_prog` 元件的内存镜像。
- 若某关卡的 LevelSpec 提供 `isa` 预设（OVERTURE / LEG），IDE 自动加载对应配置，玩家无需从零声明。

### 6.3 调试器

单步 / 继续 / 断点；寄存器面板；内存查看器（`mem_probe`）；反汇编视图；当前 PC 高亮。

## 8. 持久化

### 8.1 电路文件格式（JSON）

```jsonc
{
  "format": "tc-circuit",
  "version": 1,
  "level": "ch1-04-and-gate",
  "instances": [
    { "id": "i1", "def": "nand", "x": 120, "y": 80, "rot": 0,
      "params": {}, "state": null }
  ],
  "wires": [
    { "id": "w1", "from": { "inst": "i1", "port": "out" },
      "to": { "inst": "i2", "port": "a" } }
  ],
  "customComponents": []
}
```

### 8.2 存档（localStorage）

- 键：`tc.progress.v1`
- 内容：每关完成状态 + 三项最佳指标 + 综合最佳分；已解锁组件集合；自定义组件蓝图库；设置项。
- 导出/导入：整包 JSON 下载/上传，便于备份与跨机器迁移。
- 版本迁移：`storage.ts` 内维护 `migrate(data, fromVersion)`，加载旧档时自动升级。

## 10. 测试策略

每个阶段交付前必须全部通过。

1. **内核单元测试**（Vitest）：基础门真值表；稳定化不动点；不稳定回路抛错；`tick` 的边沿语义（快照先于写回）；`reset` 幂等；反馈回路（锁存器、振荡器）行为符合预期。
2. **关卡判定测试**：每关附**参考解**（用最少基础门搭出的 fixture）与**反例**（少一个门/接错一根线）。参考解必须通过，反例必须失败。
   - 反例验证的是「判定器有区分力」，不是「能跑」。
3. **全关卡回归**：跑完 82 关的参考解，断言 Gate/Delay/Tick 三项指标与记录的期望值一致（防止内核改动默默改变评分口径）。
4. **评分器测试**：自定义组件展开后 Gate 计数正确；嵌套蓝图；宽位组件展开；最长路径延迟计算。
5. **存档测试**：往返序列化稳定性、旧版本迁移。
6. **UI 冒烟测试**：用 Playwright 打开构建产物，进入第 1 关、放两个 NAND、连线、点 Tick、断言真值表出现通过标记。截图存档。
